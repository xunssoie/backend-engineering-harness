## Phase 1. 개선 대상 확정

### 목적
이슈와 작업 브랜치를 확보하고, 대상 API가 요청 1회에 어떤 쿼리를 날리는지 호출자와 확정한 뒤 `record.md`를 만든다.

### 선행 조건
- 대상 API가 주어졌다. 비어 있으면 중단하고 호출자에게 묻는다.
- 진행 중인 다른 대상이 없다. 있으면 그 대상이 Phase 9까지 끝난 뒤 시작한다.

### 참조 파일
- `.claude/skills/optimize-performance/template/PERF-template.md`

### 절차

1. 이슈 번호를 확보한다.
   - 주입된 `issue`가 있으면 이슈를 조회해 번호, 제목, 상태를 보고하고 이 이슈로 진행할지 확답을 받는다.

     ```bash
     harness work-context --no-base
     ```

   - `CLOSED`면 그 사실을 함께 알리고 확답 전까지 넘어가지 마라.
   - `issue`가 null이거나 호출자가 다른 이슈를 원하면 `open-issue` 스킬로 이슈와 브랜치를 확보한다.

2. 대상이 여러 개면 하나로 좁힌다 (`SKILL.md`의 **대상 진행 규칙**).
   - 목록을 보고하고 어느 것부터 할지 묻는다. 순서를 스킬이 정하지 마라.
   - 나머지는 "이 대상이 Phase 9까지 끝난 뒤에 진행한다"고 알린다. 대기 목록을 파일로 만들지 마라.

3. 슬러그를 정하고 호출자에게 알린다. 이 슬러그가 대상 디렉토리 이름이다.
   - 경로의 마지막 세그먼트를 케밥 케이스로 (`/api/v1/items/popular` → `popular`).
   - 마지막이 경로 변수(`{id}`)면 그 앞 세그먼트.
   - 같은 이슈의 기존 대상과 겹치면 앞 세그먼트를 하나 더 붙인다 (`items-popular`).
   - 경로가 같고 메서드만 다르면 메서드를 접두로 (`post-orders`).

4. 실행 경로를 진입점부터 리포지토리까지(Controller → Service → Repository, 프로젝트의 레이어 순서대로) 읽고,
   **예상 쿼리를 호출자에게 먼저 묻는다** (`SKILL.md`의 **역할 경계**).
   - 재료만 펼친다: 각 레이어의 파일 경로와 호출되는 Repository 메서드 이름까지.
   - 묻는다: "이 API가 요청 1회에 날리는 쿼리를 나열해보시겠습니까?"
   - 답을 실제 코드와 대조해 **누락분과 오차만** 짚는다. 특히:
     - 지연 로딩 지점. fetch join 없이 컬렉션에 접근하면 컬렉션마다 쿼리가 붙는다.
     - batch size가 걸린 컬렉션은 N번이 아니라 `ceil(N / size)`번이다.
     - 인증 필터, 인터셉터, 이벤트 리스너처럼 대상 API 밖에서 붙는 쿼리. 인증 필터가 DB를 보는지 코드로 확인한다.
       서명만 검증하는 필터라면 인증 경로에서 쿼리가 보이는 것 자체가 관측 대상이다.
     - 메서드 하나가 여러 쿼리로 쪼개지는 경우.
   - 호출자가 막히면 그때 목록과 근거 코드 위치를 제시한다.
   - 사전 관찰로 인덱스 유무를 적을 때 마이그레이션 파일을 근거로 쓰지 마라. 선언이 DB에 있다는 근거가 못 된다.
     Phase 2의 스키마 드리프트 점검에서 실측하므로 여기서는 `미확인`으로 둔다.

5. 인증 방식을 확인한다. 대상 컨트롤러가 인증 사용자 파라미터를 받는지, 인증 필터가 어느 헤더를 읽는지, 토큰 발급 코드의 클레임을 본다.
   `perf.tokens`(헤더, 접두어, 클레임 이름, 키 인코딩)와 어긋나면 그 사실을 알리고 설정을 맞추게 한다. **대상**의 인증 칸에 적는다.

6. `.claude/resources/perf/{이슈번호}/{슬러그}/record.md`를 `template/PERF-template.md` 구조 그대로 만든다. **이번 대상 것 하나만.**
   - **대상**을 채운다. 예상 쿼리 목록은 4에서 확정한 것.
   - 같은 이슈의 다른 대상이 만든 `seeds.sql`, `tokens.json`이 있으면 그대로 공유한다. 대상 디렉토리에 복사하지 마라.

### 출력
- `record.md` 생성, **대상**에 실행 경로, 인증, 예상 쿼리 목록
- `harness perf-progress {record.md} --phase 1 --mark ✅`

> 다음 Phase 조건: 이슈 번호와 슬러그를 확보했고 예상 쿼리 목록이 `record.md`에 적혔을 때 → Phase 2
>
> Skip 조건: 없음
