## Phase 9. 결과 보고

### 목적
사이클 전체를 요약해 보고하고, `record.md`를 PR 본문의 근거로 쓸 수 있는 상태로 마무리한다.

### 선행 조건
- Phase 8에서 종료가 판정되었거나 호출자가 종료를 선택했다.

### 참조 파일
- `.claude/skills/optimize-performance/template/report.md`

### 절차

1. `record.md`의 **최종 요약**을 채운다. 최초(`-0`)와 최종(마지막 상태 번호)을 비교한다.

   ```bash
   harness perf-delta --dir {대상 디렉토리} 0 {마지막 n} --labels 최초,최종
   ```

   출력 표를 옮기고 `llmRows` 항목만 직접 채운다. 적용한 기법을 사이클 순서대로 나열한다. 개선 없이 끝난 사이클도 빼지 말고 적는다.

2. Phase 7에서 추가한 마이그레이션이 운영 DB에 어떤 영향을 주는지 한 줄로 적는다.
   로컬에서 즉시 끝난 인덱스 추가가 운영 규모에서는 다를 수 있다. 운영 행 수를 모르면 모른다고 적는다. 추정치를 지어내지 마라.

3. 산출물 정리를 제시한다.

   ```bash
   # 토큰은 실 JWT다. 남은 대상이 없을 때만 지운다
   rm -f "$PERF_DIR/tokens.json"
   ```

   - 같은 이슈에 측정하지 않은 대상이 남아 있으면 토큰을 지우지 말고 그 사실을 알린다.
   - 시드 데이터를 남길지 호출자에게 확인한다. 지우는 방법은 시드 모듈 README의 **시드를 지울 때**.
   - `seeds.sql`, 새로 만든 시드 모듈, `record.md`, 측정 산출물은 근거이므로 남긴다. 커밋 여부는 호출자에게 확인한다.

4. 진행 상태를 마무리한다. 재개 메모에 완료 사실과 남은 대상을 적는다.

   ```bash
   harness perf-progress {record.md} --phase 9 --mark ✅ --memo "완료. {남은 대상 / 남은 대상 없음}"
   ```

5. 보고서를 렌더링해 그대로 보여준다. 수치는 **최종 요약**의 값만 넘긴다. 받지 못한 값을 추정해 채우지 마라.

   ```bash
   harness render-report optimize-performance --data '{"endpoint": "{HTTP} {경로}", "cycles": {n}, "techniques": "{1. 기법 → 2. 기법}", "independent": "{요청당 쿼리, 읽은 행/반환 행, 접근 방식의 최초 → 최종}", "dependent": "{p95, p99, RPS의 최초 → 최종}", "endReason": "{Phase 8 판정 표의 조건}", "migration": "{마이그레이션과 영향 / 스키마 변경 없음}", "record": "{record.md 경로}"}'
   ```

6. 남은 대상을 확인한다. 보고를 몰아서 하지 마라.
   Phase 1에서 알린 대기 목록이 있으면 다음 대상을 진행할지 묻고, 진행하면 그 대상의 Phase 1부터 새로 시작한다.
   앞 대상의 측정값을 물려쓰지 않는다. 이슈 공용 산출물만 공유한다.

### 출력
- `record.md`의 **최종 요약** 완성, 진행 상태 Phase 9 ✅
- `tokens.json` 삭제 (남은 대상이 없는 경우)
- 렌더링한 보고서

### 실패 처리
- 개선 없이 종료된 경우에도 보고한다. 무엇을 시도했고 왜 효과가 없었는지 적는다.

> 다음 Phase 조건: 같은 이슈에 대상이 남아 있으면 → Phase 1 (새 슬러그 디렉토리).
> 없으면 스킬 종료. 테스트는 `write-test`, 커밋은 `commit-push`, PR은 `open-pr`로 이어간다. 이 스킬은 커밋하지 않는다.
>
> Skip 조건: 없음
